# AniNotes refactor & maintenance plan

Refactor the ~2,300 lines of hand-written source to eliminate ~800 lines of anime/manga duplication, fix real bugs (first-run crash, rename race, network-on-settings-render, dead auth error handling), remove dead code, complete the frontmatter type feature, and add unit tests. No new features beyond that.

## Hard constraints (nothing breaks for existing users)

- **Persisted identifiers stay**: `data.json` keys (`tokenAL`, `animeNoteT`, `allowUserNoteNames`, …), command IDs, the `man: "man"` frontmatter marker (stored inside users' notes), the `man-revive-sync/al` protocol handler (tied to the registered AniList OAuth redirect URI), and default note dirs.
- **Template output stays byte-identical** (`$safename` rules, defaults) so a sync after the refactor doesn't rename or rewrite existing notes differently.
- Toolchain unchanged: npm + esbuild, same release artifacts.

## Phase 1 — Cleanup and hygiene

- Delete dead code: `src/tools/fs.ts` (broken leftover), `src/models/common.ts` (unused), the `ALOAuthURLData` field in `main.ts`, and all commented-out blocks (`main.ts:109-150` old sync + SampleModal, `settings/general.ts:40-51`, stray heading comments).
- Remove the five dead settings (`syncOnStartup`, `startupDelay`, `backgroundSync`, `backgroundSyncInterval`, `dateFormat`) from `settings.ts` and `constant.ts`.
- Internal renames only: `MANPlugin` → `AniNotesPlugin`, `MANSettings` → `AniNotesSettings`, `Handlebars`/`hb` imports of the Jsonata engine → `engine`, `my-plugin-tabs` CSS class → `aninotes-tabs` (in `settings.ts` + `styles.css`).
- `tsconfig.json`: enable full `"strict": true` (keeping `noUncheckedIndexedAccess`), fix resulting errors (e.g. `media!` non-null assertions in sync, `fm.ALId as number` casts → guarded checks).
- Standardize imports to relative paths (currently a mix of `baseUrl` aliases and relative), then drop `baseUrl` from tsconfig.
- `package.json`: move `obsidian` from dependencies to a pinned devDependency (it's an esbuild external, never bundled; `latest` is unsafe).
- README: mark `$blockquote`/`$image` helpers as done (both are implemented and registered).

## Phase 2 — API layer consolidation (`src/api/`)

- New `src/api/anilist.ts` merging `anime.ts` + `manga.ts`: one `requestUrl`-based fetch, one GraphQL query builder parameterized by media type (the only real difference: `episodes` vs `chapters`/`volumes` fields), exposing `getUserMediaList(mediaType, …)`. `api/constant.ts` gains the shared `ANILIST_GRAPHQL_URL` (currently hardcoded 3×) alongside the OAuth constants.
- Extract the pure query-string builder into an obsidian-import-free module so it's unit-testable.
- `tools/graphql.ts`: `gqlData` now throws with the first GraphQL error message instead of silently ignoring `errors`.
- `api/auth.ts`: move `requestUrl` calls inside the try blocks (both `exchangeALCode` and `getUserInfo` currently have dead catches), check HTTP status, validate the token response shape (an AniList 4xx body is currently cast to `OAuthTokenSchema` and saved as a "token"), and fix the stray-`'}` error string typo.

## Phase 3 — Unified sync engine (`src/commands/sync-user-list.ts`)

One parameterized implementation (media type, settings accessor, notice nouns) replaces the two 106/107-line clones. Bug fixes folded in:

- **First-run crash**: `vault.adapter.list(notesDir)` currently runs before any try/catch and throws when the notes dir doesn't exist — create the folder if missing and wrap the whole command body in try/catch with a user Notice.
- **Rename race**: renames are currently fire-and-forget (`.catch(() => {})`) and can collide with the create/update pass — await all renames first, surface failures instead of swallowing them, and compile the filename template once instead of per-file.
- Replace `processFrontMatter`-as-a-reader (a write API used ~2× per file just to read) with `vault.cachedRead` + `parseYaml` frontmatter parsing.
- `sync-all-lists`: run each sync in its own try/catch so a manga failure doesn't skip manga (or vice versa).
- OAuth protocol handler: after a successful token exchange, fetch the profile and show a success/failure Notice (currently silent).

## Phase 4 — Settings

- New `src/settings/media-notes.ts`: shared note-template settings renderer (TypeSelectionModal, property rows, drag-to-reorder with the drag-over-highlight bug fixed, single `iconMap` — currently defined 4×) parameterized for anime/manga. Replaces the two ~380-line near-identical files with one shared module plus two thin wrappers.
- `settings/general.ts`: the profile refresh currently fires an authenticated HTTP request inside a button *builder* (i.e. merely opening settings hits the network) — move it to the button's click handler.
- `fetchUserDataAtStartup` (which today actually means "fetch when settings open"): honor its name — fire it from `onload` via `workspace.onLayoutReady` when enabled; settings render becomes passive.
- `loadSettings`: deep-merge nested defaults (`animeNoteT`, `mangaNoteT`, `apiFetchOptions`) so future default additions reach existing users; arrays replace wholesale.
- Replace the `private renderX = renderX` field-grafting pattern in `settings.ts` with plain methods.

## Phase 5 — Frontmatter type coercion (completing the existing feature)

`buildFrontmatterFromEntries` in `template/frontmatter.ts` honors `FrontmatterEntry.type`: `text` unchanged (current behavior), `number` → finite `Number()` else string, `checkbox` → boolean (parsing "true"/"false"), `list` → arrays pass through / single values wrapped, `date`/`datetime` → validated string. Existing notes with default `text` entries are unaffected.

## Phase 6 — Tests and verification

- Add vitest + `npm run test` script; tests for Jsonata helpers (`$safename`, `$capital`, `$date`, `$callout`, `$blockquote`, `$image`, `$link`, `$wikilink`), `htmlToMarkdown`, `buildFrontmatterFromEntries` (incl. type coercion), and the query builder. Pure modules are kept free of `obsidian` imports so they're testable.
- Add a test step to `.github/workflows/lint.yml`.
- Verify locally: `npm run build` (tsc noEmit + esbuild), `npm run lint`, `npm test` all green.
- Manual sanity checklist left for you (I can't run Obsidian here): connect AniList account, sync anime/manga lists, check settings tabs, verify an existing note isn't renamed or mangled.

## Not in scope (noted as follow-ups)

- Token refresh via `refresh_token` (per your choice).
- Rotating the committed AniList OAuth client secret — inherent to published Obsidian plugins, but forks/abuse share your app quota; worth doing at your leisure.

Net effect: hand-written source drops from ~2,300 to roughly ~1,500 lines, all duplicated modules become single shared implementations, and the known bugs are fixed. No commits will be made unless you ask.
